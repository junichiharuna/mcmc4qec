# 有限PBS tailのeffective adapterとreport IPC環境

元v3 adapter、execution_binding、bridge_overlayと既存v8設定を固定原本として保持する。
新しい設定でも最初にbase_configの外部byte pinを読み、固定原本v3のvalidate_configを元設定に対して実行する。
新reportを旧execution_bindingの許可hashへ偽装して検証しない。
新設定は元設定の全top-level keyを保持し、`finite_report_authority` だけを追加する。
変更できる既存fieldはreport_environment、environment_acceptance、明示した8つのoperational pathだけとする。
merge_root、parent_environment、basis、source_root、source_sha256、adapter_sha256、parallel_merge、科学的設定は元設定と同一に保つ。
8つのpathはjournal_root、handoff_path、census_config_root、census_job_root、independent_config_root、independent_controls_root、report_config_root、report_job_rootとする。
各pathは別の正規化された絶対pathとし、作成時のfreshnessは設定作成側で確認し、実行後の再検証では出力の存在だけを失敗条件にしない。

authorityはbase_config pin、effective_sources、ipc、path_delta、native_terminal pinを持つ。
ipcは固定変換helperのpin、base_report pin、派生report pin、有限timeout_secondsを持つ。
base_reportは旧設定のparallel_merge.reportと同じpinでなければならない。
固定IPC helperのderive_reportを元reportの実bytesと旧設定のbridge/runner実bytesに適用し、新reportのbytesと完全一致することを検証する。
初期のtimeoutは4時間の親PBS予算から最低300秒を残した1〜14100秒に限定する。
この予算は実測による完走保証ではない。

新report environmentは元report environmentのreport source_sha256、resolved_sources、import_origins、import_prependだけを変更できる。
native、runtime、Python、pythonpathと他moduleのpinを保持する。
新report専用cluster_scripts directoryは元source directoryと別にする。
native acceptanceはbase_config、parent/basis、新environment、新report、IPC source/timeoutと一致し、approved_delta_verified/native_bootstrap_verifiedがtrue、scientific_configuration_changedがfalseでなければならない。
外部pinで固定したnative terminalが同じ受入jobのF・exit0・run_count1であることも検証する。
受入はIPC付きreport sourceのnative/import環境に関するものであり、科学的再現や本計算完了を意味しない。

load_adapterは固定原本v3 adapterのbytesをその元filenameでロードする。
validate_configだけを新版strict validatorへ明示的に差し替え、元v3 validatorはbase_configの検証に必ず使い続ける。
report execution roleのcollection suffix変換は別仕様の固定collection helperをouter loaderが1回だけ適用する。
元driverのcompiled source hashは元adapterの実行intentへ記録され、effective source pinsとoverride内容は別の明示provenanceに記録する。
run/configure/transform_driver/final_reportと科学bodyは固定原本の関数を保持する。
outer controllerはmerge_root、parent_environment、adapter_sha256、handoff_pathを従来どおり参照できる。
大きいmetadata検証は共通の有限PBS action内で行う。

受入fixtureでは旧validatorの必須実行、科学field改変拒否、正確な4field環境差分、IPC source改変拒否、native証跡不一致拒否、旧report hashへの偽装拒否、限定path差分とtruthfulなoverride provenanceを確認する。
ローカルでは受入テストを実行しない。
