# 通常経路で不要になった待受6本の終了

2026年10月24日、所有者からPCの負荷を下げるため不要なmcmc4qec Pythonプロセスを終了するよう依頼を受けた。
稼働中の22本を調べ、実処理1本と待受21本に分類した。
親プロセスが存在しないことだけでは不要と判定しなかった。

## 停止対象を決めた根拠

固定済みの通常経路の資源規則は、全条件の実測時間と追加hash予算の和を1.5倍し、600秒を加えて300秒単位に切り上げ、上限を24時間としている。
原本のcandidate metadataとhashを照合すると、完了済み11条件だけで必要時間の下界は123,000秒、約34.17時間となる。
残る条件の寄与は正であるため、全12条件でも固定済みの通常経路の24時間上限を満たせない。
これは資源規則に対する下界の確認であり、11条件を全12条件の正式な選択・比較結果として採用したものではない。
資源規則・科学計算入力・経路guard・qsub制御は変更していない。

このため、通常経路のselector完了後にしか開始しない6段の待受は、現在の固定規則の下では到達不能と判定した。
各プロセスのcommand・開始時刻・実行sourceのhashを照合し、journalには待機記録と初期intentだけがあり、遠隔処理・qsub・結果回収に進んでいないことを確認した。
子プロセスはconsole hostだけで、計算やSSHの子プロセスはなかった。

| 終了PID | 通常経路の段階 |
|---|---|
| 43972 | seed censusの準備待ち |
| 47848 | seed censusの実行待ち |
| 21496 | 独立計時の準備待ち |
| 33616 | 独立計時の実行待ち |
| 19116 | 最終報告の準備待ち |
| 49488 | 最終報告jobの実行待ち |

停止直前にprocessの開始時刻を再確認してから、この6本だけを終了した。
停止前のworking set合計は約62.4MiBであり、これだけで数GBの解放になるとは扱わない。
対応するconsole hostも終了した。
既存journalとsourceは保持し、自動再起動は行わない。

## 維持した処理

Python 20604の索引作成とその親、C3T2の分配・準備・qsub・回収の待受を維持した。
通常経路の親準備とselectorも、全12条件が揃った後の正式な資源判定と代替経路への引き継ぎに必要なので維持した。
代替経路の準備・経路guard・census・独立計時・最終報告の待受も維持した。
必要な16本が稼働していることを終了後に確認した。
今後、固定資源規則を変更して通常経路を利用する場合は、停止済み6段について既存journalを保持した再開設計が必要となる。

同directoryの`cleanup.py`は実行したscriptの保存コピーであり、実際の実行場所は`output/cleanup_unreachable_waiters_20261024/`だった。
このscriptを現在のPIDに対して無条件に再実行しない。
