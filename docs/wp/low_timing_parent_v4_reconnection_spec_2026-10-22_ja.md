# 全12条件の計時準備を親環境v4へ接続する

## 対象と不変条件

planned C3T1/C3T2の8時間版を受け入れた親環境v4へ、全12条件の入力準備と独立計時seed censusの準備を接続する。
稼働中のsource、旧環境、失敗記録、既存の計算jobは変更しない。
全12条件の候補、元の選択規則、24時間の資源制約、seedの固定割当、qsubによる最大2ノード制約を保持する。
環境の接続確認を、全12条件の計算完了や独立計時の完了と扱わない。

## 受入条件

既存census basisの構築手順を別版へ複製し、新親環境のhashとremote pathを固定する。
元の56 namespace・3,963,562割当の保存監査とsource relocationを確認し、新たなseed生成や本census実行を行わない。
新inventoryと親準備は8候補だけでは準備も投入も行わず、全12候補と各候補の固有環境を要求する。
census準備は新basisと親環境の実hash、source、selector完了の契約を検証する。
引継ぎは新旧sourceが不変で、旧processの実commandと生成時刻が一致し、計算子processがなく、出力が待機履歴だけである場合に限定する。
過去の全履歴を保持し、引継ぎmarkerとclaimは版別に排他的に作成する。
改変されたsource・履歴・環境・引継ぎ権限、準備着手済み出力、重複claimを拒否する受入テストを先に用意する。
新待機processの実生存、新版intent、待機観測、旧履歴のhash不変を確認して接続を受け入れる。

## 適用限界

後続の全12条件の資源確定・selector・独立seed census・計時・最終報告は別工程であり、未実施を維持する。
資源上限に収まらなければ条件を減らさず停止し、既存の分割方針案に従って別途設計する。
