# 非公開ヘルパーを含む strict 型検査（2026-10-15）

基準は `35ed7f3` の独立 worktree であり、科学的アルゴリズム、乱数消費、公開引数、ノイズ密度の意味を変えずに型契約を補った。
初回の `mypy --strict src/mcmc4qec` は 20 ファイルで 270 件のエラーを検出した。
非公開ヘルパー、内部配列、Optional キャッシュ、GF(2) 操作、診断、BAR 補助関数、回路補助関数へ注釈を加え、既存 24 source ファイルすべての strict 検査を通した。
`binary` と `categorical` の検証済み戻り値は `NDArray[np.uint8]` とした。
`Problem` の非依存消費側は従来の暗黙の型消去を `Problem[Any]` と明示し、既存の `Problem[P]` と sampling の引数型の結び付きは保持した。
JSON と外部 backend の動的境界に残る `Any` を、配列・数値計算の戻り値と区別した。
JSON の辞書コピー、NumPy stub の戻り値、事前検証済み Optional の限定箇所では型付き変数または `cast` を用いた。
新たな `type: ignore` は追加せず、adapter に既存の `union-attr` ignore は検証済み logical map の明示へ置き換えた。
FastStepper の二値分岐は、初期化時に二値行でのみ設定される `binary_logs is not None` で絞り込み、分布計算の hot path に追加の cast 呼び出しを置かない構成とした。

`pyproject.toml` の既定を strict にし、CI と package・consumer 型テストでも `--strict` を明示した。
全体の `ignore_missing_imports` は外し、PEP 561 情報が不足する optional scientific backend の名前空間に限定した。
ldpc の公開 API の implicit re-export は ldpc 名前空間だけで許可し、mcmc4qec 自体の strict 検査は緩めていない。

検証環境は Windows、Python 3.11.9、NumPy 2.4.6、mypy 2.3.1 である。
`python -m mypy --strict src/mcmc4qec` は `Success: no issues found in 24 source files` だった。
`tests/test_typing.py`、`test_initial_states.py`、`test_faststep.py`、`test_estimation.py`、`test_convergence.py`、`test_adapters.py`、`test_categorical_kernels.py` の計 7 ファイルは 89 passed / 27.24 秒だった。
この中には valid consumer の受入と、誤ったノイズ引数を持つ invalid consumer の拒否が含まれる。
`git diff --check` は成功した。
全 suite、統合後の新規回路 module、wheel、remote CI の検証はこの分担では未実施であり、統合担当の最終確認に委ねる。
研究リポジトリの変更、commit、push は実施していない。

高速化担当と重なる `faststep.py`、`sampling.py`、`adapters.py`、回路担当と重なる `circuit/model.py`、`circuit/baselines.py`、`circuit/proposal.py` は統合時にアルゴリズム変更側を保持して注釈を合わせる必要がある。
新規回路 stepper の effects 配列は基底の list of lists と異なるため、統合後に共通の読み取り用 Sequence 型へ合わせる必要がある。

## 統合後の確認

回路担当が共通effects tableを `list[np.ndarray]` に統一し、統合時に追加された高速化helperにも注釈を補った。
統合後の `mypy --strict src/mcmc4qec` は新回路2moduleを含む26sourceすべてで成功した。
全体のsource/wheel検証結果は [統合報告](final_report_2026-10-15_ja.md) に記録する。
