# WP-H 独立レビュー

## 判定と範囲

4本のテンプレート、専用テスト、完了メモを依頼書の科学的注意とCLI規約に照らして確認した。
既定例の小さいCSS行列は`CSSCode`が可換性、論理演算子とstabilizerの可換性、論理基底の完全性と独立性を検査する。
小さい状態空間ではノイズの`log_prob`を全列挙して正規化を確認し、大きい状態空間では未検査と表示する。
デコーダーの生出力は`output_kind`で意味を明示し、correctionはsyndromeと論理写像への整合を検査する。
独自failure predicateの決定性は同じ入力への反復呼び出しで調べ、stabilizer不変性を仮定せず、stabilizer flipを有効にする場合の利用者の確認責任をコメントに記している。
条件付きchainから絶対`P_L`を求めず、CSSのBARではデコーダーを固定し、exactまたは失敗観測のあるMC anchorを使う。
回路テンプレートはDEMの潜在機構を対象とし、物理回路faultのbaselineとは区別している。
全テンプレートが`--seed`から検査用と推定用の乱数を派生させ、出力先が研究リポジトリ配下かをディレクトリ作成前に判定し、最終`SUMMARY`行のキー集合をマニフェスト通りに保つ。

## 指摘と対応

`byo_decoder.py`は12量子ビットを超えてexactを実行しない場合にもMC推定値を`Exact P_L`と表示していたため、MCのみを表示する分岐に修正した。
`byo_noise.py`は`log_prob`の正規化だけを調べ、`sample`の形やsupportをサンプリング前に確認していなかったため、少数試料の形、二値性、supportの検査を追加した。
ノイズの`sample`を全ゼロ固定にする反例では`log_prob`の正規化が1でも両者の分布が一致しないため、有限の事前検査では分布一致を保証できないとdocstringと出力に明記した。
大きい入力では`checks_passed=false`を実施した検査の失敗と誤読しうるため、未検査と部分検査を表す旨を出力に追加した。

## 実行した確認

optional環境のPython 3.11で`python -m pytest tests/test_examples_templates.py -q`を実行し、13 passedを確認した。
テストは4本の`--quick`、マニフェストの`SUMMARY`キー、結果ファイル、壊した行列、非正規化ノイズ、不正なノイズ試料幅、不正なデコーダー出力、研究rootの拒否を含む。
ノイズの反例を一時的なメモリ上の差し替えで実行し、`sample`が全ゼロを返す一方で正規化検査が1.0を返し、`log_prob`が状態111に正の確率0.006を与えることを確認した。
大きい符号の分岐は13量子ビットのCSS符号とゼロcorrectionデコーダーをメモリ上で構成して実行し、exact列挙を行わずMC推定値だけを表示することを確認した。

## 残る限界

有限個の試料と反復呼び出しでは、任意の利用者実装についてサンプラーと密度の同一性、デコーダーやfailure predicateの全入力での決定性、MCMCの収束を証明できない。
大きい入力のsyndromeと状態の検査は無作為な部分集合に限られ、ノイズの正規化は未検査である。
利用者が編集した実符号と外部デコーダーの網羅的検証、全suite、installed wheel、CIはこのレビューでは未実施である。
