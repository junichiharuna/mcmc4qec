# Public API

The package ships a `py.typed` marker. Public entry points and internal helpers carry type annotations; validated matrix/vector inputs accept NumPy arrays and supported array-like values such as nested lists. `Noise[P]` and `Problem[P]` connect a noise implementation to its parameter type, including custom JSON-compatible parameters. A custom binary model may omit `alphabets`, in which case `Problem` uses binary coordinates. Runtime validation still checks dimensions, normalized densities, and decoder output meaning. The package and consumer examples are checked with `mypy --strict`; optional backend imports retain explicitly scoped typing exceptions.

The names below cover every top-level export in `mcmc4qec.__all__`. Code factories, decoder constructors, circuit tools, and initialization helpers are also available from their corresponding submodules. The contracts require deterministic decoding and normalized noise probabilities on the entire stated state space. A probability is for the complete experiment represented by the model; a phenomenological result is not a per-round rate.

| Names | Purpose and main constraints |
| --- | --- |
| `Model`, `Noise`, `Decoder` | Protocols for state validation, normalized `log_prob`, sampling, logical prediction, and JSON-compatible metadata. |
| `BinaryLinearModel`, `CSSCode` | Binary syndrome/observable model and validated CSS matrices. `CSSCode.phase_flip_model()` uses `hx` for syndrome, `lx` for logical observables, and `hz` for stabilizer flips; `IndependentBitFlip(code.n)` supplies its binary product noise. `logical_basis="paired"` requires identity cross-pairing; explicit `"independent"` accepts invertible cross-pairing without rebasing rows. Invalid dimensions, nonbinary matrices, or CSS commutation raise `ValueError`. |
| `CallableDecoder`, `CallableFailure`, `Problem` | Bind deterministic logical predictions and one failure definition across exact, MC, and MCMC. Identifiers and settings remain caller-maintained provenance. |
| `IndependentBitFlip`, `DepolarizingNoise`, `PhenomenologicalNoise` | Independent binary, joint I/X/Y/Z categorical, and bounded spacetime noise. Zero support has log probability `-inf`. |
| `DepolarizingModel`, `PhenomenologicalModel` | Full Pauli observables and explicit repeated-measurement boundaries; `PhenomenologicalModel` requires rounds, boundary choices, representation, and data-noise type. |
| `KernelConfig`, `SamplingConfig` | Kernel weights sum to one without implicit normalization; separate lazy probability, burn-in, thinning, chain count, finite initialization budget, product-noise Z fast path, and bounded decoder cache. Physical circuit faults allow `single`, `zanella`, and `circuit_single`; `cluster` additionally requires explicit `circuit_groups`. Circuit `stabilizer` remains unsupported. |
| `exact`, `direct_mc`, `sample_faulty` | Exact finite enumeration (limited by `max_states`), fixed-trial MC with a 95% Wilson interval, and failure-conditioned MCMC. They return `Result`; `sample_faulty` may raise `InitializationError`. |
| `spawn_seeds` | Deterministic independent child integer seeds for caller-managed workers. |
| `diagnose`, `evaluate_convergence` | Multiple-chain weight-trace IAT, ESS, split R-hat, and four post-hoc consistency checks. A complete four-check verdict requires an independently estimated direct-MC conditional variance and different initial populations. These diagnostics do not establish convergence or ergodicity. |
| `DiagnosticsConfig`, `diagnostic_report`, `analyze_traces` | Optional numeric ACF, block-length scans, and circular-block bootstrap of observable means. Enable alongside sampling with `diagnostics=True` or a config, or analyze existing Results/numeric traces afterwards. No plotting dependency is required. |
| `Result`, `__version__` | JSON-serializable result and package version. A zero observed MC count retains an upper bound and does not establish zero true mass. |
| `DecoderAdapter`, `PyMatchingAdapter`, `matching_from_check_matrix` | Wrap a decoder with explicit `output_kind`; physical corrections require `logical_map`. The check-matrix helper rejects columns of degree above two. PyMatching correlation choice must be explicit. |
| `SectorDecoder`, `HistoryDecoder` | Compose sector predictions or transform an explicit syndrome history for a decoder. They do not change the joint noise distribution. |
| `from_stim_dem`, `from_stim_circuit`, `matching_from_dem` | Build latent DEM model/noise, convert a Stim circuit with explicit approximation options, and make a graphlike DEM decoder. These require optional Stim/PyMatching as applicable. |
| `estimate_logical_error`, `EstimationResult`, `bennett_log_ratio`, `OverlapError` | Anchored BAR ladder, its result, an adjacent log-ratio primitive, and the insufficient-overlap error. A standard ladder keeps one failure set; the explicit decoder-dependent mode is approximate. |
| `minimum_weight_coset_representative`, `logical_representatives` | Exact static CSS coset minimization by small-rank enumeration or proven-optimal MILP. The latter needs SciPy; a timeout raises rather than returning an unverified result. |
| `minimum_weight_initial_state`, `maximum_weight_initial_state`, `random_logical_sector_initial_state`, `observable_sector_initial_state` | Static CSS initialization candidates: `sector="x"` for bit-flip and `sector="z"` for phase-flip. Check both noise support and actual failure under your decoder/predicate before passing one to `sample_faulty(initial_state=...)`. Independent logical bases are handled through the crossing matrix. |
| `CircuitFaultModel`, `CircuitFaultNoise`, `FaultLocation`, `stim_noise_locations`, `uniform_fault_noise` | Physical Stim noise locations, exclusive per-location fault categories, and product likelihoods. Native Stim noise probabilities are not silently reused by the model. |
| `PhysicalFaultProposal`, `surface_logical_idle_circuit`, `surface_logical_idle_problem` | Add/remove/replace one physical fault with its proposal ratio; construct the 2d-round midpoint rotated-surface baseline. The DEM builds its PyMatching decoder, while sampling stays on exclusive physical locations. |

`mcmc4qec.codes` provides `make_toric_code`(d), `make_surface_code`(d), `make_asymmetric_toric_code`(d1, d2), `make_hgp_hamming`(), `make_bb_code`(l, m, a_terms, b_terms), `make_bb_code_72`(), `make_bb_code_108`(), `make_bb_code_144`(), `make_steane_code`(), `make_concatenated_steane_code`(levels), and `concatenate_css`(outer, inner). The HGP-based factories need optional `ldpc` and `bposd` from `mcmc4qec[codes]`; all return validated `CSSCode`. `make_bb_code` accepts exponent-pair terms in Z_l × Z_m; duplicate terms cancel over GF(2). The Hamming and some BB bases use `logical_basis="independent"` and retain their input row order.

`mcmc4qec.decoders` provides `mwpm_decoder`(code, *, errors="X"), `bposd_decoder`(code, p, *, errors="X", **kw), `depolarizing_mwpm_decoder`(code), and `depolarizing_bposd_decoder`(code, p, **kw). The first two predict X-error observables using `hz`/`lz` by default, or Z-error observables using `hx`/`lx` with `errors="Z"`; the sector constructors return X/Z predictions in model order. BP-OSD uses a fixed channel prior and decoder settings, so changing it across a BAR ladder requires the explicit approximate mode. Sector decoding is a decoder approximation, while depolarising noise still samples the joint I/X/Y/Z distribution. MWPM requires graphlike columns; BP-OSD needs optional `ldpc`.

`exact(problem, p, max_states=...)` returns an absolute logical failure probability and, when failure mass is positive, a failure-conditioned nonzero-coordinate count. `direct_mc(problem, p, trials=..., seed=...)` uses a fixed trial count. `sample_faulty(problem, p, config=..., seed=..., initial_state=...)` returns states shaped `(chains, samples, n)`; it does not return absolute `P_L`. `estimate_logical_error(problem, ladder, anchor=None, config=None, ...)` returns per-rung absolute estimates, log estimates, intervals where available, warnings, and diagnostics. Its automatically computed or explicitly provided anchor must match the first rung's model, noise, decoder, failure definition, and probability. `OverlapError` means the sampled adjacent ensembles had no observed bidirectional support overlap.

### Automatic BAR anchor

Both `anchor` and `config` can be omitted. `config=None` uses `SamplingConfig()`: 1,000 retained samples, 100 burn-in steps, thinning 1, one chain, Z/H weights 0.7/0.3, `cluster_k=2`, and lazy probability 0.05. Model-specific requirements still apply, including explicit circuit kernel configuration.

With `anchor=None`, BAR computes the first rung's absolute probability using `exact` when the product of `problem.alphabets` is at most `anchor_max_states=4096`; otherwise it runs `direct_mc` for exactly `anchor_trials=10000` trials. Set `anchor_max_states=0` to force MC. The enumeration limit must be a nonnegative integer and the trial count a positive integer; Boolean and noninteger values are rejected. An explicit `anchor=Result` bypasses these automatic-budget settings and retains the existing anchor validation. In `p_dependent_decoder_approx` mode, the automatic anchor uses the decoder built for the first rung.

Automatic MC uses a separate child seed, independent of the rung and BAR-bootstrap RNG streams, and its variance contributes to the final uncertainty. The same seed and configuration reproduce the run. MC with zero failures or failures on every trial raises `ValueError`; no adaptive trial extension occurs. Increase `anchor_trials`, change the first noise rate, or provide a valid explicit anchor. Exact enumeration with zero failure mass also raises; a positive mass that underflows the probability representation remains usable through its finite `log_estimate`. Enumeration validation errors are propagated rather than hidden by an MC fallback. Few MC failures can still make uncertainty unreliable; inspect warnings.

`result.metadata["anchor"]["source"]` is `"automatic"` or `"provided"`. Anchor metadata records the method, trial/failure counts when applicable, and MC seed; automatic budgets are recorded in `result.metadata["config"]`. These settings choose a bounded starting calculation, not a target precision or a guarantee of mixing or interval coverage.

### BAR uncertainty

`estimate_logical_error(..., uncertainty="block_bootstrap")` retains the default circular-block bootstrap and its existing controls. Set `uncertainty="cross_chain"` to estimate uncertainty from independent chains: pair adjacent-rung chains by chain index, solve BAR separately for each pair, and divide the sample covariance of their log ratios by the number of chains. The covariance retains dependence between adjacent ratios through their shared rung; the independent anchor's log variance is then added. Both methods retain the same pooled BAR point estimates for the same sampling seed and configuration. Cross-chain uncertainty requires `SamplingConfig(chains=2)` or more; one chain or an unknown method raises `ValueError`. The selected method is recorded in `result.metadata["uncertainty_method"]`. The existing `bootstrap_log_ratio_covariance` field remains specific to bootstrap; cross-chain covariance is recorded in `result.metadata["cross_chain_log_ratio_covariance"]`.

Cross-chain intervals assume independent, adequately mixed chains and a useful large-sample approximation for per-chain BAR ratios. They do not account for finite-chain bias or establish nominal coverage, and increasing the number of chains does not remove a bias shared by all starts. The choice of uncertainty method does not change burn-in, initialization, chain count, or convergence checks. The associated paper's cross-chain standard error is defined for observable means; applying it to BAR ratios is an uncertainty estimate implemented here, not a reproduction or validation of the paper's figures. In bootstrap mode, `bootstrap_replicates=0` disables ladder uncertainty; it does not disable cross-chain uncertainty.

Two chains are the computational minimum, not a precision recommendation. The intervals use a normal approximation with a 1.96 standard-error multiplier on the log scale; with few chains, the estimated between-chain variance and this approximation can be unreliable. Check repeated-seed coverage and sensitivity to chain count and length for the intended problem.

### Default statistical errors and optional detailed diagnostics

Statistical uncertainty is returned by default: direct MC has its Wilson interval, BAR has probability intervals and `log_standard_errors`, and `sample_faulty` has `conditional_weight` with `conditional_weight_standard_error`. The latter is the Monte Carlo SE of the **conditional mean weight**, not an absolute failure-probability SE or the standard deviation of individual weights. It reuses the usual IAT calculation. `diagnose` also returns `mean`, `chain_standard_errors`, `mean_standard_error`, and `standard_error_method`. For K equal-length independent chains of n retained samples, the combined SE is `sqrt(sum(s_j**2 * tau_j / n)) / K`, with sample variance `s_j**2` and chain IAT `tau_j`. It assumes stationarity and does not include mixing bias. If any chain's IAT is undefined (short, constant, or nonpositive estimate), combined SE is `None`. The new Result field is optional in older JSON payloads.

Extra diagnostic computation is off by default. Pass `diagnostics=True` or `diagnostics=DiagnosticsConfig(...)` to `sample_faulty` or `estimate_logical_error`. Sampling returns the numeric report in `result.diagnostics["trace_analysis"]`; BAR returns one in `result.diagnostics[i]["trace_analysis"]` for each rung. A diagnostic report's bootstrap interval concerns that rung's conditional weight mean; **BAR probability intervals retain their own uncertainty calculation and RNG**. Enabling diagnostic bootstrap does not enable BAR error bars if the latter were explicitly disabled.

`DiagnosticsConfig(max_lag=None, block_sizes=None, bootstrap_replicates=200, seed=0)` controls only the extra analysis. `max_lag` is inclusive (default `min(100, n-1)`); lags, IAT and block sizes count retained samples. `sample_spacing` records `SamplingConfig.thin` when known and consistent. No extra burn-in removal or thinning occurs. `block_sizes` is a nonempty tuple of distinct positive integers at most n; the default includes 1 and powers of two leaving at least four batches when possible. `bootstrap_replicates=0` skips only diagnostic bootstrap; 1 is invalid. The separate seed defaults to 0; `None` generates and records fresh entropy. Sampling states, acceptance, and BAR estimates/intervals are identical when toggling extra diagnostics with the same sampling seed.

The detailed report contains:

| Fields | Interpretation |
| --- | --- |
| `rhat`, `rhat_method` | Classical raw split Gelman–Rubin R-hat; requires two chains and eight retained samples. Odd lengths drop the middle observation. This is not rank-normalized or folded R-hat. |
| `chain_iat`, `chain_ess`, `iat_mcse`, `cross_chain_se` | Geyer initial monotone paired IAT, chain ESS, IAT-based mean MCSE, and standard error across independent chain means. IAT can be below one for negative serial correlation. `ess` sums chain ESS and is **not** the pooled-mean ESS. |
| `acf.lags`, `acf.chains` | Per-chain FFT autocorrelation, normalized by lag-zero covariance without an n/(n-lag) correction; constant series return `None`. |
| `blocking` | Non-overlapping batch-mean SE for each block size. `samples_used_per_chain`, `discarded_per_chain`, `mean`, and `mean_difference` expose discarded tails and the resulting mean shift. |
| `bootstrap.blocks` | Independently resample circular blocks within each chain to its original length, then average all chains. Each block size returns a bootstrap SE and a percentile 95% interval. Chain boundaries are never concatenated. |
| `warnings` | Missing/degenerate estimates and assumptions. Short runs and few blocks/draws do not establish nominal interval coverage. |

`diagnostic_report(result_or_results, config=..., observable=..., observable_name=...)` analyzes existing Results. Its default observable is weight; custom callbacks receive a copy of each state and must return a finite scalar and supply a name. Results combined in one report must represent independent chains of the same target distribution, with equal lengths. For numeric observables, `analyze_traces(array, observable="name", ...)` accepts finite `[chain, sample]` arrays or one vector, and returns the same core fields. All reports contain JSON-compatible numbers, lists and `None`, not plot objects or raw state copies.

Method references: [Stan's raw split R-hat and MCSE discussion](https://mc-stan.org/docs/2_40/reference-manual/analysis.html) and [Geyer's batch-means discussion](https://www.stat.umn.edu/geyer/3701/notes/mcmc-bayes.pdf). Unlike modern Stan diagnostics, this release retains the existing raw split R-hat and per-chain IAT convention. No statistic certifies convergence or coverage.

If any per-chain BAR solve lacks bidirectional overlap, cross-chain ladder intervals are unavailable and a warning is returned; the pooled point estimate is retained. No failing chain is silently dropped from the uncertainty calculation.

The default Z/H mixture uses weights 0.7/0.3, `cluster_k=2`, one chain, and a separate 0.05 lazy probability. Rejections and lazy moves remain chain steps. `KernelConfig(zanella_fastpath=True)` applies only to recognized product noises. `SamplingConfig(cache_cap=N, cache_policy="research_clear" | "lru" | "freeze")` configures decoder caching; `research_clear` is a soft cap checked every ten steps, while the other policies impose strict caps. A custom `Noise.log_prob(state, p)` must return the normalized log probability on the same state space used by `sample`; invalid values and mismatched state dimensions are rejected. Built-in noises use scalar probabilities or explicit parameter dictionaries. The ordinary samplers (`exact`, `direct_mc`, and `sample_faulty`) also accept a custom noise implementation's JSON-compatible parameter type; their `Problem[P]` and `p: P` annotations preserve that relationship. BAR ladder coordinates remain limited to numeric values or dictionaries. For phenomenological models, `p={"data": ..., "measurement": ...}` describes the entire bounded experiment. `PhenomenologicalModel(data_noise="phase_flip", ...)` uses binary Z data faults and X-check measurement faults; its history shape and number of measurement coordinates follow `hx`. Optional decoders must return a deterministic prediction of logical observables; adapters never infer whether output is a correction from its shape. Circuit fault models support `single`, `zanella`, and `circuit_single` mixtures, plus `cluster` with explicit `circuit_groups`; circuit `stabilizer` must remain zero. For example, use `KernelConfig(single=0.3, zanella=0.7, cluster=0, stabilizer=0)` for Z+OBF. Location probabilities retain their variable alphabets; zero padding in the fast path is never a proposal category.

Circuit H groups are disjoint nonempty tuples of location indices with identical channels and ordered fault alphabets within each group. Groups are selected uniformly independently of the state; unavailable branches self-loop, and omitted locations are unchanged by H. Full density and shared failure checks remain necessary with heterogeneous rates and zero support. `PhysicalClusterExchange` is available from `mcmc4qec.circuit`; see the [group example](tutorial_en.md#physical-circuit-faults). Its occupancy preservation means H alone is generally reducible. Exact built-in circuit model/noise pairs with the standard failure predicate use cached effect differences; subclasses and custom predicates fall back to general evaluation.
