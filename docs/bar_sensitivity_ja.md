# toric d=3 の BAR 区間と direct MC の感度評価

## dev5 の追加評価

WP-P は pooled BAR 点推定を維持した `cross_chain` 不確かさと、論文領域および dev4 領域の固定 cohort 比較スクリプトを追加した。
論文の平均重みの cross-chain 標準誤差は BAR 区間の名目被覆を保証しないため、被覆を独立した反復 seed で測る。
Q の高速化を統合した dev5 main で保存 600・2400・9600 の長さ比較と、4 構成・2 領域・両anchorの固定20 seed被覆比較を完了した。
実行済みの短い pilot は後述の正式表に混ぜなかった。
dev4 の20 seed中13という下記の過去の探索結果はdev5でも同設定・同seedで再現したが、名目被覆の保証には使えない。
論文領域の p=0.03 と dev4 領域の p=0.22 を区別し、短い chain、点推定の偏り、区間幅の過小評価の候補を全 seed と同一軌道上の二手法で調べた。
四条件が合格しても混合、エルゴード性、無偏性、区間被覆の証明にはならない。

## 対象と計測方法

2026-10-01 に Windows の Python 3.11 で、`make_toric_code(3)`、静的 X bit-flip、固定された重みなし MWPM decoder、同一の失敗定義を使った。
`examples/workflows/pl_curve.py` の既定設定で d=3 の ladder は `[0.30, 0.26, 0.22]`、各 rung は 4 chain、保存 600、burn-in 180、Z/H 既定混合、MC anchor 1500 試行、独立 MC 確認 1200 試行、bootstrap 30 回である。
seed 2026 から 2045 までを事前に定め、各 seed から anchor、BAR、独立 MC の seed を `spawn_seeds` で分けた。
BAR と独立 MC の区間はいずれも名目 95% で、BAR には混合と block bootstrap の仮定が付く。
感度表は特記しない限り seed 2026 から 2033 の同じ 8 seed に対して一つの設定だけを変えた探索である。
表の被覆率に併記した角括弧は反復 seed を二項試行とみなした参考的な 95% Wilson 区間であり、名目被覆の証明ではない。
出力は `benchmarks/bar_sensitivity.py` が `*_runs.csv` と `*_summary.csv` に保存し、各実行時間は 10 分未満だった。

block の pilot は p=0.22、4 chain、保存 600、burn-in 180、seed 1984 の重み trace で、最大 IAT は 26.5995 だった。
保存数だけの二行は基準と同じ block 8 を明示指定し、旧計測の二行は `bootstrap_block_length=None` の立方根規則が保存数とともに block 6/11 へ変わった参考値である。
旧計測の seed ごとの点推定は block 8 固定の再計測と同一で、区間だけが変わった。
block 8 固定の保存 200/1200 の実行時間は 39.40/131.43 秒で、旧自動 block 6/11 の 44.21/148.40 秒とは別の計測である。
各 seed の実際の最大 chain IAT は変動する。
この固定 p の独立 bit-flip 対では `log rho_b/rho_a = n log((1-b)/(1-a)) + w log(b(1-a)/(a(1-b)))` なので、非定数の log-density difference trace の自己相関と IAT は重みと一致する。
BAR の非線形な sigmoid score の IAT まで一致するとは限らず、一般の相関ノイズでは log-density difference を重み IAT で代用できない。
block 比較は同じ chain 軌道を bootstrap だけ変えており、点推定は同一である。
seed 2026 では block 3、27、107 の BAR 区間上限は順に 0.5579、0.5700、0.5703 で、全て exact 0.6027 を外した。
同 seed では保存数 1200・block 8 固定で BAR 0.5765、区間 [0.5520, 0.6020]、旧自動 block 11 では同じ点推定で [0.5508, 0.6034]、burn-in 600 では BAR 0.6107、区間 [0.5807, 0.6421] となった。
これらの値は短い chain の点推定が動くことを示すが、どの操作が一般に bias を除くかは確定しない。

## 利用者向けの設定指針

まず各 rung の独立 chain で重み、BAR の密度比 score、chain 間差、初期状態差を調べ、block 長を少なくとも観測 IAT 程度から試し、数倍へ動かして区間幅の安定性を確認する。
今回の 600 標本と既定 block 8 は観測した重み IAT より短く、区間の過小評価を疑う理由があるが、長い block だけで点推定の偏りは直らない。
保存数を block 8 固定で 600 から 1200 / chain に増やした 8 seed 比較では被覆が 4/8 から 7/8、平均区間幅が 0.06321 から 0.05299 となったため、研究用評価ではこの規模を pilot の出発点とし、独立 seed と長さを増やして安定性を再確認する。
ladder は有限の交差 support と双方向 overlap を各隣接組で確認し、overlap が低い箇所は刻みを細かくする。
今回の 0.30–0.22 範囲では粗い ladder でも平均最小 overlap が 0.451 であり、刻み不足を主因とは判断しない。
MC anchor と確認用 direct MC の seed は分離し、非 anchor 点の独立 MC 区間や列挙できる問題の exact 真値を確認する。
診断が良くても BAR 区間の名目被覆は保証されないため、短い実行例の非交差をそのまま警告として残す。

## 再実行と限界

基準は `PYTHONPATH=src` で `%USERPROFILE%/AppData/Local/Programs/Python/Python311/python.exe benchmarks/bar_sensitivity.py --scenario baseline --seeds 20 --out <一時ディレクトリ>` を実行した。
感度は同じ script の `--scenario` に表の名前を与え、`--seeds 8 --truth-file <baseline_summary.csv> --trust-truth-file` で先行 exact 真値を再利用した。
保存数だけの比較は `--scenario samples_short` と `--scenario samples_long` を使い、benchmark が `bootstrap_block_length=8` を明示する。
最初の参考計測は最終修正前の同名 scenario を `bootstrap_block_length=None` で実行し、元 CSV を一時出力先に `samples_short_default_cube_*` と `samples_long_default_cube_*` として保全した。
最終 script の `samples_short_auto` と `samples_long_auto` は、この参考計測の自動 block 設定を再現する。
`low_p` は p=0.10 を新たに exact 列挙したため `--truth-file` を付けなかった。
真値 CSV の再利用は利用者が同じ toric d=3、同じ MWPM、同じ failure 定義を使ったことを確認する明示的な操作であり、異なる問題の CSV を自動識別する機能ではない。
benchmark の CSV は一時ディレクトリに書かれるため、上の per-seed 表と感度要約をこの文書に残した。
20 seed と各 8 seed の Wilson 幅は広く、設定の最適化や 95% 被覆の確証、大きな符号や低 p の研究精度は未実施である。

## dev5 の事前固定した保存長比較

dev5 では同じ toric d=3、ladder `[0.30,0.26,0.22]`、MC anchor 1500 試行、4 chain、burn 180、block 8、bootstrap 30 反復を固定し、seed 2026–2045 の全20本を保存長 600、2400、9600 で比較した。
各長さで同じ seed の anchor と chain 系列を用い、9600 は計算時間だけを理由に seed 2026–2035 と 2036–2045 の二回へ事前分割した。
exact 真値は失敗重み histogram から検証済み cache で計算した `0.602662564701594` であり、20 seed の欠落・重複と真値・source provenance は集計時に検査した。

| 保存数/chain | MC anchor BAR 平均 | 平均 bias | seed 間 SD | 平均の SE | BAR exact 被覆 | seed 2026 点推定 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 600 | 0.590749 | −0.011914 | 0.025610 | 0.005727 | 13/20 | 0.534471 |
| 2400 | 0.601433 | −0.001230 | 0.012282 | 0.002746 | 20/20 | 0.590558 |
| 9600 | 0.599411 | −0.003251 | 0.006966 | 0.001558 | 20/20 | 0.593408 |

同 seed の点推定差の20本平均とその SE は、2400−600 が `+0.010684 ± 0.004678`、9600−600 が `+0.008663 ± 0.005146`、9600−2400 が `−0.002022 ± 0.002497` だった。
保存数とともに seed 間散らばりは小さくなり、短い600の大きな負偏差は長い二条件で縮んだが、20 seed だけで系統 bias の有無や `1/sqrt(N)` 則を確定しない。
9600 の MC anchor 平均偏差は約 `−2.09 SE` だが、固定した同じ anchor のばらつきが残る。
元の CSV の各点推定を MC anchor で割り、cache から得た exact anchor `0.7076851364881606` を掛ける補助的な再換算では、平均 bias は保存数順に `−0.010479`、`+0.000274`、`−0.001737`、seed 間 SD は `0.024223`、`0.011622`、`0.007136` だった。
同じ20本の log BAR 比の seed 間 SD は `0.041104`、`0.019177`、`0.011772` で、長さを増やしたときの比自体の散らばりも減った。
再換算は新しい MCMC 実行ではなく同じ軌道の派生量であり、既定の MC anchor を使う主表と区別する。
MC anchor は全長で同じ seed と試行数なので、その有限試行による変動は保存数を増やしても残る。
9600 で観測された MC 点推定 SD `0.006966` は単純な anchor 分散の目安より小さいが、同じ20本の anchor 値と BAR 比の標本相関が `−0.59118` で、分散分解の負の標本共分散がこれを説明する。
独立な seed 生成の設計に反する真の負相関を主張するものではなく、anchor 由来の分散目安を有限20本の標本 SD の下限とも扱わない。
組み込み bit-flip と固定 MWPM の既定開始は noise から失敗条件付き target を棄却法で標本化するため、この保存長差を burn 180 の初期過渡と断定できない。
有限相関、非線形 BAR の有限標本効果、少数 chain と区間の不確かさは残る。
20/20 被覆でも95% Wilson 下限は約 `0.839` で、名目95%被覆や block 8 の十分性を保証しない。
追加 burn・chain 感度は持続的 bias の確証がないため今回の事前計画では実施せず、今後の候補として残す。
全行と再計算用のコードは [dev5 長さ CSV](wp/data_dev5/length/aggregate/cohort_runs.csv)、[集計表](wp/data_dev5/length/aggregate/cohort_summary.csv)、[派生量](wp/data_dev5/length/length_derived.json) に保存した。
